# Приёмка сетевого теста DriveGauge

Дата автоматической проверки: 16 ноября 2026 г.

## Текущий статус

- Автоматизируемая часть ТЗ: **PASS**.
- Blocker / critical / major / minor дефекты кода: **0** по итогам двух независимых проверок.
- Ручная проверка на реальном SMB/NFS/WebDAV: **BLOCKED** — сетевой том не смонтирован.
- GitHub Release: **не публиковать до ручной приёмки**.

## Что подтверждено автоматически

- отдельный `NetworkBenchmarkEngine` и отдельный worker-процесс;
- worker упаковывается в `Contents/Helpers` и запускается без shell;
- приложение и helper собраны только для `arm64`;
- сетевые проверки не выполняются на `MainActor`;
- адаптивный объём и ограниченное время теста;
- точный монотонный счётчик записанных и прочитанных байтов;
- watchdog для подготовки, передачи, синхронизации и общего времени;
- остановка worker, адресный `SIGKILL` после grace period и ожидание stdout/stderr до EOF;
- продолжение после повреждённого JSON и события с чужим `runID`;
- отмена менее чем за 3 секунды в integration fixture;
- отменённый запуск не проходит completion gate к сохранению результата;
- безопасный UUID-файл через `O_EXCL` и удаление только точного пути;
- существующий marker с совпавшим run ID не изменяется и не удаляется;
- сценарии permission, ENOSPC, injected insufficient space, crash и stall;
- bounded diagnostic log с фазой и кодом ошибки;
- миграция legacy SQLite-строки и roundtrip сетевых metadata;
- локальный smoke-тест `BenchmarkEngine` на 8 МиБ;
- `git diff --check`;
- deep codesign приложения и helper;
- проверка DMG.

Основная команда автоматической проверки:

```bash
bash scripts/test-network-benchmark.sh
```

Она запускает:

1. protocol/worker safety self-tests;
2. integration tests production `NetworkBenchmarkEngine` с реальным worker;
3. локальный smoke-тест production `BenchmarkEngine`.

## Обязательная ручная проверка

Перед выпуском подключить реальный SMB, NFS или WebDAV-том и выполнить следующие пункты.

### Обычный запуск

- [ ] Сетевой том появился в списке и распознан как сетевой с правильным типом ФС.
- [ ] Асинхронная проверка доступа завершилась без подвисания окна.
- [ ] Кнопка старта правильно заблокирована при недостатке места или запрете записи.
- [ ] Стандартный сетевой тест запустился отдельным адаптивным профилем.
- [ ] Во время записи растёт точный счётчик подтверждённых байтов.
- [ ] Во время чтения счётчик начинается заново и монотонно растёт.
- [ ] Окно свободно перемещается; элементы интерфейса не зависают.
- [ ] Отображаются elapsed, ETA и пояснение `Mac → сеть → сервер → ФС/накопитель`.
- [ ] Успешный тест сохранился в истории с сетевыми metadata.

### Остановка

- [ ] Во время записи нажать `ОСТАНОВИТЬ`.
- [ ] Интерфейс вернулся в стабильное состояние не позднее 3 секунд.
- [ ] Остановленный тест не появился в истории успешных.
- [ ] В корне тома не осталось `.drive-gauge-*.tmp` от этого запуска.

### Потеря соединения

- [ ] Начать тест и физически отключить сеть либо остановить доступ к серверу.
- [ ] Через 3 секунды появилось сообщение об отсутствии передачи.
- [ ] Watchdog завершил зависший тест согласно лимиту фазы.
- [ ] DriveGauge остался отзывчивым.
- [ ] Ошибочный тест не сохранился как успешный.
- [ ] После восстановления сети проверить результат cleanup либо понятное предупреждение о точном оставшемся temp-файле.

### Безопасность пользовательских данных

- [ ] До теста создать контрольный пользовательский файл и записать его checksum.
- [ ] После успешного, остановленного и аварийного тестов checksum не изменился.
- [ ] Ни один пользовательский файл не переименован и не удалён.
- [ ] Удалялся только точный UUID temp-файл текущего запуска.

1. Зафиксировать сервер, протокол, версию macOS и результаты ручных пунктов в этом документе.

3. Рекомендуемый следующий релиз: `1.2.0` с новым build number.
4. Выполнить полную release-сборку.
5. Проверить `arm64`, deep codesign и DMG.
6. Создать новый подписанный Sparkle appcast.
7. Только затем сделать финальный commit, tag и GitHub Release.
